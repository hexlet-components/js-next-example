Каталог городских мероприятий на Next.js для [курса «JS: Next» на Хекслете](https://ru.hexlet.io/courses/js-next). Приложение показывает события, сохраняет условия поиска в URL, принимает заявки и разрешает организатору менять только свои события.

## Требования

- Node.js 26 или новее и pnpm 12. Установка Node.js описана в [инструкции Хекслета](https://github.com/Hexlet/ru-instructions/blob/main/nodejs.md), установка pnpm в [официальной инструкции](https://pnpm.io/installation).
- Make для коротких команд из этого README. Те же команды можно выполнять через pnpm.

## Запуск

Клонируйте репозиторий и подготовьте приложение.

```bash
git clone https://github.com/hexlet-components/js-next-example.git
cd js-next-example
make setup
```

В _.env.local_ появятся адрес готового API и настройка cookie для локального HTTP.

```dotenv
EVENTS_API_URL=http://localhost:4000
COOKIE_SECURE=false
```

В первом терминале запустите готовый API.

```bash
make api
```

Программа напечатает `Events API http://localhost:4000`. API работает отдельным процессом, хранит учебные данные в памяти и возвращает исходное состояние после перезапуска.

Во втором терминале из каталога репозитория запустите приложение.

```bash
make dev
```

Откройте `http://localhost:3000/events`. Список содержит шесть мероприятий. Поиск «Прогулка» находит три события, а вторая страница показывает «Прогулку по парку».

## Учебные сценарии

| Адрес | Что проверить |
| --- | --- |
| `/events` | Список, поиск и пагинация с сохранением параметров в URL |
| `/events/1` | Карточка, интерактивная кнопка и заявка с новым счётчиком |
| `/events/missing` | Сообщение об отсутствующем событии |
| `/login` | Вход организатора |
| `/events/1/edit` | Изменение своего события, отказ без сессии и для чужого владельца |

| Организатор | Почта | Пароль | Свои события |
| --- | --- | --- | --- |
| Анна | `anna@example.com` | `password123` | 1, 3, 5 |
| Борис | `boris@example.com` | `password123` | 2, 4, 6 |

Сессия действует час. Next.js сохраняет токен в HttpOnly-cookie и проверяет пользователя при открытии редактирования и внутри действия сохранения. API повторно проверяет владельца. После выхода форма в старой вкладке больше не сохраняет изменения.

Локальная настройка `COOKIE_SECURE=false` нужна для HTTP. На публичном HTTPS-адресе используется `COOKIE_SECURE=true`. Этот учебный API слушает только 127.0.0.1 и предназначен для локальных примеров.

## Готовый API для своего приложения

API находится в _api/server.mjs_ и не требует установки пакетов. Его можно использовать отдельно от готового фронтенда, сохраняя тот же контракт, что в уроках.

```bash
node api/server.mjs
```

Перед запросами Next.js должен получить `EVENTS_API_URL=http://localhost:4000` из своего файла _.env.local_. Браузер обращается к страницам Next.js, серверные компоненты и действия обращаются к API.

| Запрос | Назначение |
| --- | --- |
| `GET /events?q=&page=1&pageSize=2` | Список `{ items, total, page, pageSize }` |
| `GET /events/:id` | Карточка или 404 |
| `POST /events/:id/applications` | Заявка с полями `name` и `email`, ответ 201 или 422 |
| `POST /sessions` | Вход с `email` и `password`, ответ `{ token }` или 401 |
| `GET /session` | Пользователь по токену сессии |
| `DELETE /session` | Отзыв сессии |
| `PATCH /events/:id` | Изменение `title` владельцем, отказ 401 или 403 |

Запросы сессии и редактирования передают токен заголовком `Authorization: Bearer <token>`. Данные, идентификаторы и ответы совпадают с примерами курса.

## Ожидание и отказ API

Остановите обычный процесс API сочетанием `Ctrl+C`. Задержка позволяет увидеть сообщение загрузки.

```bash
API_DELAY_MS=1500 make api
```

Режим отказа возвращает 503 при чтении событий.

```bash
API_FAIL=1 make api
```

После запуска API обычной командой `make api` кнопка «Попробовать снова» возвращает карточку. Перезапуск сбрасывает данные и сессии.

## Сборка и проверки

Остановите dev-сервер и соберите приложение. API продолжает работать в другом терминале.

```bash
make build
make start
```

Для проверки используются production-сборка, тесты контракта API и браузерные сценарии. Каждый тест получает API с исходными данными, процессы останавливаются после прогона.

```bash
make lint
make typecheck
make build
pnpm exec playwright install chromium
make test
```

Проверки форматов, ссылок, опечаток и workflows собраны в mise. Команда `mise run check` запускает тот же набор, что workflow Check. Workflow CI также собирает приложение и выполняет тесты.

В _osv-scanner.toml_ записано временное исключение до 17.12.2026 для [ReDoS в picomatch](https://github.com/advisories/GHSA-fc5q-39xc-vjpf). Пакет используют только Knip и Stylelint с шаблонами файлов из репозитория. Исправленная версия пока не выпущена, runtime-зависимости приложения этой находки не содержат.

## Состав

| Каталог | Содержимое |
| --- | --- |
| _app/_ | Страницы App Router, состояния маршрутов и серверные действия |
| _components/_ | Клиентские кнопки и формы |
| _lib/_ | Серверное чтение событий и проверка сессии |
| _api/_ | Готовый локальный API со стартовыми данными |
| _tests/api/_ | Проверки HTTP-контракта API |
| _tests/browser/_ | Проверки пользовательских действий в собранном приложении |
